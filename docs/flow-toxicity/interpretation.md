## บทคัดย่อ

เอกสารนี้อธิบายวิธีอ่านค่า Flow Toxicity indicator โดยอิงเอกลักษณ์ทางคณิตศาสตร์ที่พิสูจน์ไว้ใน [calculation.md](calculation.md) จุดสำคัญคือ indicator นี้แสดงสองปริมาณที่ตอบคำถามต่างกัน — ปริมาณแรก ($N$, แท่ง) วัดแรงสุทธิที่เหลือหลังการหักล้าง ปริมาณที่สอง ($T$, เส้นม่วง) วัดแรงรวมของทั้งสองฝั่งก่อนหักล้าง **ระยะห่างระหว่างสองปริมาณนี้คือสารสนเทศหลัก** ไม่ใช่ค่าสัมบูรณ์ของอันใดอันหนึ่ง

## 1. โครงสร้างการแสดงผล

Pane แสดงสองชุดข้อมูลบนสเกลเดียวกัน (`priceScaleId: "toxicity"`)

| องค์ประกอบ | ปริมาณ | ช่วงค่า | สี |
|-----------|--------|---------|-----|
| Histogram | $\lvert N \rvert$ (Net Flow) | $[0,1]$ | เขียว `#26a69a` เมื่อ $N \ge 0$, แดง `#ef5350` เมื่อ $N < 0$ |
| เส้น | $T$ (Toxicity) | $[0,1]$ | ม่วง `#ab47bc` |

ความเข้มของแท่งขึ้นกับ `hotThreshold`: เข้มเมื่อ $\lvert N \rvert \ge \theta$, จาง (opacity 0.35) เมื่อต่ำกว่า

**เส้นม่วงอยู่เหนือหรือเท่ากับยอดแท่งเสมอ** — เป็นผลจากอสมการสามเหลี่ยม ไม่ใช่เรื่องบังเอิญ ถ้าเห็นแท่งทะลุเส้นแปลว่ามีบั๊ก

## 2. อุปมาชักเย่อ

อุปมาที่ตรงกับคณิตศาสตร์:

| ในเกมชักเย่อ | ในสูตร |
|--------------|--------|
| แรงที่ทั้งสองฝั่งออกรวมกัน | $T = B + S$ (เส้นม่วง) |
| เชือกขยับไปเท่าไหร่ | $\lvert N \rvert = \lvert B - S \rvert$ (แท่ง) |
| แรงของฝั่งที่แพ้ | $\min(B,S) = \dfrac{T - \lvert N \rvert}{2}$ (ครึ่งหนึ่งของช่องว่าง) |

โดย $B$ = แรงซื้อรวม, $S$ = แรงขายรวม (นิยามใน [calculation.md §4](calculation.md#ขั้นตอนที่-4-การแยกส่วน-decomposition))

สองฝั่งดึงแรงเท่ากัน → **แรงเยอะแต่เชือกไม่ขยับ** = เส้นม่วงสูง แท่งเตี้ย
ฝั่งเดียวดึงอยู่ → **แรงเยอะและเชือกวิ่ง** = เส้นม่วงสูง แท่งสูงตาม

นี่คือเหตุผลที่ต้องมีสองชุด: ถ้ามีแต่แท่งอย่างเดียว จะแยก "เงียบจริง" ออกจาก "สู้กันเดือดแต่เสมอ" ไม่ได้เลย

## 3. ตารางตีความหลัก

| แท่ง $\lvert N \rvert$ | ช่องว่าง $T-\lvert N \rvert$ | ความหมาย | ฐานคณิตศาสตร์ | แนวทาง |
|---|---|---|---|---|
| **สูง** | **แคบ** | ฝั่งเดียวคุมเกมจริง แรงเกือบทั้งหมดไปทางเดียว | $\min(B,S) \to 0$ | เทรนด์ชัด — อย่าสวน, ต้นทุนไล่ราคาสูง |
| **เตี้ย** | **กว้าง** | ซื้อขายกันหนักมากแต่หักล้างกันหมด | $\min(B,S)$ ใหญ่ | สู้กันอยู่ — ระวังเหวี่ยง, รอ breakout ตัดสิน |
| **เตี้ย** | **แคบ** (เส้นม่วงต่ำด้วย) | ไม่มีใครออกแรงเลยทั้งสองฝั่ง | $B+S \to 0$ | เงียบจริง — ไม่มีอะไรน่าสนใจ |
| **สูง** | **กว้าง** | เป็นไปไม่ได้ | $\lvert N \rvert \le T$ | ถ้าเห็น = บั๊ก |

### 3.1 เหตุใดแถวที่ 1 จึงถูกต้อง

ช่องว่างแคบ $\iff T - \lvert N \rvert \to 0 \iff 2\min(B,S) \to 0 \iff$ ฝั่งที่แพ้แทบไม่มีแรงเหลือ

กรณีสุดขั้ว $\min(B,S) = 0$ หมายถึงทุกแท่งในหน้าต่างเอียงทางเดียวกันหมด ซึ่งให้ $\lvert N \rvert = T$ พอดี (ทดสอบแล้วได้ $1.000000$ ทั้งคู่)

### 3.2 เหตุใดแถวที่ 4 จึงเป็นไปไม่ได้

จากสมการงบประมาณ $\lvert N \rvert + \text{gap} = T \le 1$ — ความสูงของแท่งกับช่องว่างแลกกันภายใต้งบจำกัด ถ้าแท่งสูง 0.8 ช่องว่างต้องไม่เกิน 0.2 โดยบังคับ

## 4. Directional Efficiency

นิยาม $D = \dfrac{\lvert N \rvert}{T} \in [0,1]$ — สัดส่วนของแรงทั้งหมดที่ดึงไปทางเดียวกัน

ข้อดีคือ $D$ **ไร้หน่วยและ normalize แล้ว** จึงแปลเป็นอัตราต่อรองได้โดยตรง:

$$\frac{\text{ฝั่งชนะ}}{\text{ฝั่งแพ้}} = \frac{1+D}{1-D} \qquad\qquad \frac{\text{ฝั่งชนะ}}{T} = \frac{1+D}{2}$$

| $D$ | ฝั่งชนะ : ฝั่งแพ้ | สัดส่วนฝั่งชนะ | อ่านว่า |
|-----|-------------------|----------------|---------|
| 0.00 | 1 : 1 | 50% | เสมอกันพอดี |
| 0.20 | 1.5 : 1 | 60% | เอียงเล็กน้อย |
| 0.33 | 2 : 1 | 67% | เอียงชัด |
| 0.50 | 3 : 1 | 75% | ฝั่งเดียวคุม |
| 0.60 | 4 : 1 | 80% | คุมเบ็ดเสร็จ |
| 1.00 | $\infty$ | 100% | ทางเดียวล้วน |

> $D$ ยังไม่ได้ implement เป็น series ในโค้ด — คำนวณเองได้จาก `netFlow` และ `toxicity` ที่แสดงอยู่แล้ว

## 5. การตั้ง hotThreshold

### 5.1 มันทำอะไร

`hotThreshold` ($\theta$) **ควบคุมเฉพาะความสว่างของแท่ง ไม่กระทบเส้นม่วงและไม่กระทบค่าที่คำนวณได้**

```
|N| >= θ  →  แท่งสีเข้ม
|N| <  θ  →  แท่งสีจาง (opacity 0.35)
```

เป็นเครื่องมือช่วยกวาดสายตาหาช่วงที่แรงสุทธิมีนัยสำคัญ **ไม่ใช่สัญญาณซื้อขาย**

### 5.2 แปลง threshold เป็นอัตราต่อรอง

เนื่องจาก $\lvert N \rvert = D \cdot T$ เมื่อรู้ค่า $T$ ทั่วไปของเครื่องมือนั้น จะแปลง $\theta$ เป็นอัตราต่อรองได้

ตารางนี้ใช้ $T \approx 0.53$ (ค่า median ที่วัดได้จากข้อมูลสังเคราะห์):

| $\theta$ | $D$ | ฝั่งชนะชนะเท่าไหร่ |
|----------|-----|---------------------|
| 0.05 | 0.09 | 1.2 : 1 — แทบเสมอ |
| 0.10 | 0.19 | 1.5 : 1 |
| **0.15** (default) | 0.28 | **1.8 : 1** |
| 0.20 | 0.38 | 2.2 : 1 |
| 0.30 | 0.57 | 3.6 : 1 |

ทำให้ตั้งค่าได้จากคำถามที่ตอบง่ายกว่า: *"แรงซื้อต้องชนะแรงขายกี่ต่อกี่ ถึงจะเรียกว่ามีนัยสำคัญ"*

### 5.3 วิธีจูนกับข้อมูลจริง

เปิดชาร์ตหุ้นและไทม์เฟรมที่ใช้จริง ปรับจนแท่งสีเข้มโผล่ราว **10–20% ของเวลา**

- เข้มเกือบทุกแท่ง → $\theta$ ต่ำไป
- แทบไม่เข้มเลย → $\theta$ สูงไป

> **บริบททางประวัติศาสตร์:** เวอร์ชันก่อนหน้า hard-code ไว้ที่ 0.4 ซึ่งวัดแล้วพบว่าไม่เคยติดเลยแม้แต่ครั้งเดียวใน 2,951 แท่งของตลาด sideways (0.00%) และติดเพียง 0.20% ในเทรนด์แรง ทำให้ pane เป็นสีจางถาวร

### 5.4 ข้อควรระวัง

ค่า default 0.15 **ยังไม่ได้ calibrate กับข้อมูลตลาดจริง** repo ไม่มี OHLCV fixture ตัวเลขที่วัดได้บนข้อมูลสังเคราะห์คือ:

| สภาวะ | สัดส่วนแท่งสีเข้มที่ $\theta = 0.15$ |
|-------|-------------------------------------|
| Sideways / random walk | 5.4% |
| เทรนด์แรง | 53.1% |

ตัวเลข 53% ในเทรนด์แรง**น่าจะสูงเกินไป** ต้องจูนต่อ และค่าที่เหมาะสมจะต่างกันตามเครื่องมือ ไทม์เฟรม และสภาพคล่อง

## 6. ช่วงค่าที่คาดหวัง

จากการวัดบนข้อมูลสังเคราะห์ (window = 50, 3,000 แท่ง):

| ปริมาณ | Sideways | เทรนด์แรง |
|--------|----------|-----------|
| median $\lvert N \rvert$ (แท่ง) | 0.056 | 0.157 |
| median $T$ (เส้นม่วง) | 0.525 | 0.533 |
| median $D$ | 0.107 | 0.297 |

**ข้อสังเกตสำคัญสองข้อ:**

1. **ช่องว่างกว้างเป็นภาวะปกติ** เส้นม่วงเกาะแถว 0.5 ส่วนแท่งเตี้ยกว่ามาก เพราะโดยธรรมชาติแล้วแรงซื้อขายส่วนใหญ่หักล้างกันเอง ไม่ใช่ความผิดปกติ

2. **ค่าสัมบูรณ์ของเส้นม่วงแทบไม่ให้สารสนเทศ** $T$ ขยับอยู่ในช่วงแคบมาก (0.47–0.63) และแทบไม่ต่างกันระหว่าง regime สิ่งที่อ่านได้จริงคือ *ช่องว่าง* หรือ *อัตราส่วน $D$* ไม่ใช่ระดับของ $T$ เอง

> **ข้อจำกัดของตัวเลขชุดนี้:** มาจากข้อมูลสังเคราะห์ที่ไม่มี autocorrelation, volume clustering หรือโครงสร้าง microstructure จริง ค่าจากตลาดจริงอาจต่างออกไปมาก ควรวัดใหม่เมื่อมีข้อมูล

## 7. สิ่งที่ indicator นี้ไม่ได้บอก

| ไม่ได้บอก | เหตุผล |
|-----------|--------|
| ใครเป็นผู้ริเริ่มการเทรดจริง (aggressor side) | อนุมานจากรูปทรงแท่ง ไม่มี tick data |
| ลำดับเหตุการณ์ภายในแท่ง | high/low/close ไม่บอกว่าอะไรเกิดก่อนหลัง |

| ทิศทางราคาในอนาคต | ยังไม่ผ่านการ validate เชิงทำนายใน repo นี้ |
| ความเป็น informed vs uninformed flow | ต้องใช้โมเดล PIN/VPIN เต็มรูปแบบ ซึ่งนี่ไม่ใช่ |

## 8. เปรียบเทียบกับ indicator อื่น

| Indicator | ตอบคำถาม | ต่างจาก Flow Toxicity อย่างไร |
|-----------|----------|-------------------------------|
| **Volume** | เทรดกันเยอะแค่ไหน | ไม่มีทิศทาง ไม่ normalize |
| **RVOL** | ปริมาณผิดปกติไหมเทียบ baseline | normalize ตามเวลา แต่ไม่มีทิศทาง |
| **Net Flow** (แท่งของ indicator นี้) | แรงสุทธิเอียงไปทางไหน | = Chaikin Money Flow |
| **Toxicity** (เส้นม่วง) | แรงรวมทั้งสองฝั่งเท่าไหร่ | ไม่หักล้าง จับ churn ได้ |
| **Absorption** | volume เยอะแต่ราคาไม่ไป | เน้น effort-vs-result ต่อแท่ง |
| **Volume Profile (delta)** | แรงซื้อขายกระจายตามระดับราคา | มิติราคา แทนมิติเวลา — ใช้ classifier เดียวกัน |

**ความซ้ำซ้อนที่ควรรู้:** เนื่องจาก classifier อิงตำแหน่ง close ในช่วงแท่ง ค่า $N$ จึงสหสัมพันธ์สูงกับการอ่าน price action ตรงๆ (แท่งเขียวยาวติดกันหลายแท่ง) ในตลาดที่เทรนด์ชัด $N$ แทบไม่ให้ข้อมูลเพิ่มจากการดูกราฟแท่งเทียน ส่วนที่ให้ข้อมูลใหม่จริงคือ $T$ และช่องว่าง

## 9. ข้อจำกัด

### 9.1 เชิงระเบียบวิธี

1. **ไม่ใช่ VPIN** ต่างจาก Easley, López de Prado & O'Hara (2012) สามจุด — ใช้ time bars แทน equal-volume buckets, ใช้ Close Location Value แทน BVC ตามตัวบทความ, และไม่มีขั้นตอน normalize ด้วย CDF ของ volume imbalance

2. **Classifier ไม่ใช่ BVC ตามวรรณกรรม** BVC จริงใช้ $Z\left(\frac{\Delta P}{\sigma_{\Delta P}}\right)$ (CDF ของการเปลี่ยนแปลงราคาระหว่างแท่ง) ส่วนที่ใช้จริงคือ Close Location Value ซึ่งมาจากสาย Accumulation/Distribution ของ Chaikin

3. **แม้แต่ VPIN ตัวจริงก็ยังเป็นที่ถกเถียง** Andersen & Bondarenko (2014) พบว่า VPIN ทำนายความผันผวนระยะสั้นได้ไม่ดี และค่าสูงสุดเกิด*หลัง* flash crash ไม่ใช่ก่อน รวมถึงชี้ว่า VPIN สหสัมพันธ์กับ volume และ volatility โดยโครงสร้างอยู่แล้ว

### 9.2 เชิงข้อมูล

4. **ไม่มี tick data** ทำให้ทุกอย่างเป็นค่าประมาณ

5. **ไวต่อการเลือกไทม์เฟรม** window 50 แท่งบน 1m กับ 1d เป็นคนละเรื่องกันโดยสิ้นเชิง

6. **ฟีดที่ไม่มี volume จะ degrade เป็น equal-weight** ยังคำนวณได้แต่ความหมายเปลี่ยน (ไม่ถ่วงน้ำหนักด้วยปริมาณอีกต่อไป) และ**ไม่มีการแจ้งเตือนบน UI** เพราะระบบไม่มี legend ที่ render `label`

### 9.3 เชิงการใช้งาน

7. **ยังไม่ validate ว่ามี predictive power** — [`research/daily_reversal/RESULTS.md`](../../research/daily_reversal/RESULTS.md) ระบุว่าชุด indicator นี้ (VWAP bands, RVOL, Toxicity, Absorption) มีประโยชน์เป็นเครื่องมืออ่าน context และ execution cost แต่ไม่ได้รับการยืนยันว่าใช้เป็นสัญญาณเข้าเทรดเชิงกลได้

8. **`hotThreshold` ยังไม่ calibrate** (ดู §5.4)

9. **ไม่มี unit test ใน repo** เพราะฝั่ง frontend ไม่มี test framework ติดตั้งอยู่ การตรวจสอบทั้งหมดทำผ่านสคริปต์ภายนอก
