# Question Research — ตอบคำถามที่ยังไม่มีตัวเลขชัด

**อัปเดตล่าสุด:** 2026-10-01
**ใช้เมื่อ:** agent รับคำถามจากคิว (`question_queue`) หรือผู้ใช้สั่งให้ตรวจคำถามใน PORT → TOOLS → QUESTIONS
**ใช้กับ:** ทุก agent — MCP ส่งไฟล์นี้ผ่าน tool `get_question_spec` · resource `spec://question-research` · prompt `investigate_questions` (แก้ไฟล์ ไม่ต้องแก้ MCP)
**โค้ด:** `backend/routers/questions.py` · ตาราง `question*` ใน `backend/db.py`

---

## 0. หลักการ

1. **ห้ามตอบโดยไม่มีหลักฐาน** — ทุกคำตอบชี้ไปที่ zettel ที่มี URL + ประโยคที่อ้าง server ปฏิเสธ (422) ถ้าไม่ครบ และบอกทุกช่องที่ขาด
2. **อนุมานได้ แต่ต้องตรวจได้** — ถ้าไม่มีตัวเลขตรง ให้ประกอบจากร่องรอย แล้วระบุสมมติฐาน: ตัวเลขที่จะใช้ตรวจ, อ่านจากไหน, เมื่อไร, ผลแบบไหนถือว่าผิด
3. **ผู้ใช้เป็นคนปิดคำถาม** — คำตอบของ agent เป็น "เสนอ" จนกว่าผู้ใช้กดรับ; agent รับรอง / เลิกติดตามเองไม่ได้
4. **"ไม่ชัด" เป็นคำตอบที่ถูกต้อง** — ดีกว่าคำตอบที่มั่นใจแต่ผิด ให้บันทึกว่าค้นที่ไหนแล้ว และจะดูอีกเมื่อไร

## 2. สัญญาณ — ประกอบคำตอบจากร่องรอย

ไม่ต้องมีใครประกาศว่ามีงานแต่ง ถ้ารู้ว่ามีคนได้รับซอง มีการจองดอกไม้ และจองชุดแต่งงาน — แต่ต้องระวังว่าซองกับดอกไม้เข้าได้กับงานบวชและงานศพด้วย

แต่ละสัญญาณใน `question_answer(signals=[…])`:

| ช่อง | ความหมาย | บังคับเมื่อ |
|---|---|---|
| `expectation` | สิ่งที่ควรเห็นถ้าคำอธิบายนี้จริง | เสมอ |
| `result` | `FOUND` · `NOT_FOUND` · `CONTRARY` (พบสิ่งตรงข้าม) · `NOT_SEARCHED` | เสมอ |
| `finding` | สิ่งที่พบจริง | FOUND / CONTRARY |
| `zettel` | Z-ref ของหลักฐาน | FOUND / CONTRARY |
| `origin` | ต้นทางของข้อมูลจริง ๆ (ใครเป็นคนผลิตตัวเลขนี้) | FOUND |
| `diagnostic` | `true` = คำอธิบายคู่แข่ง **ไม่** ทำนายสัญญาณนี้ | — |
| `supports` | ชี้ไปทางคำอธิบายไหน | — |
| `searched_where` | ค้นที่ไหนแล้วไม่เจอ | NOT_FOUND |

กติกา:
- **สัญญาณที่เข้าได้กับทุกคำอธิบายไม่มีน้ำหนัก** — ราคาขึ้นเกิดได้ทั้งจากอุปสงค์เพิ่มและอุปทานขาด → `diagnostic: false`
- **`origin` เดียวกันนับครั้งเดียว** — AMD กับ Arm พูดเรื่องเดียวกัน = "ผู้ขาย CPU" หนึ่งทาง; สื่อสามเจ้าอ้างรายงานเดียวกัน = หนึ่งทาง
- **`NOT_FOUND` ต้องบันทึก** — การค้นแล้วไม่เจอคือข้อมูล การไม่ได้ค้นไม่ใช่
- **หาหลักฐานที่ขัดก่อน** — ถ้าเจอ ให้ลง `CONTRARY`; มี CONTRARY แล้วยืนยันระดับ CONFIRMED ไม่ได้

## 3. ระดับคำตอบ

| level | ใช้เมื่อ | server ต้องการ |
|---|---|---|
| `CONFIRMED` + `basis=NUMBER` | มีตัวเลขจากแหล่งปฐมภูมิ | `value`, `as_of`, `evidence` ≥ 1 ที่มี source `primary` (url + quote) |
| `CONFIRMED` + `basis=EVENT` | สิ่งที่รอเกิดขึ้นแล้ว | `as_of`, `evidence` ≥ 1 |
| `CONFIRMED` + `basis=CIRCUMSTANTIAL` | ไม่มีตัวเลขตรง แต่ร่องรอยอิสระชี้ทางเดียว | `alternatives` ≥ 2 · สัญญาณ FOUND ที่ `diagnostic` และ `origin` ต่างกัน ≥ 2 · ไม่มี CONTRARY · evidence ไม่อยู่ใน conflict ที่เปิด |
| `INFERRED` | มีหลักฐานบางส่วน ที่เหลือต้องสมมติ | สัญญาณ FOUND หรือ `evidence` ≥ 1 + `assumptions` ≥ 1 ครบ `statement` / `metric` / `source_hint` / `check_by` / `falsifier` |
| `UNCLEAR` | ค้นแล้วยังบอกไม่ได้ | `searched` + `next_check` |
| `UNANSWERABLE` | ข้อมูลสาธารณะไม่มีทางตอบได้ | `searched` + `next_check` (วันทบทวน) |

ถูกปฏิเสธ → อ่าน `missing` แล้วแก้ทุกข้อ หรือลดระดับ **อย่าเติมช่องให้ผ่านโดยไม่มีของจริง**

สมมติฐานที่ดี: "ถ้าเป็นเรื่องอุปทาน เมื่อปริมาณ server ของ Intel เพิ่ม ราคาเฉลี่ยจะถอย" — metric = server ASP + volume YoY · source_hint = Intel 10-Q Q3/26 · check_by = 2026-10-22 · falsifier = ปริมาณเพิ่มและราคายังขึ้น

## 4. ตรวจสมมติฐานเมื่อถึงวัน

คำถามระดับ WATCH ที่ถึง `check_by` จะกลับเข้าคิว: อ่านแหล่งใน `source_hint` → zettel EVIDENCE → `assumption_check(result=HELD|BROKEN, note=ตัวเลขที่ออกมา, zettel=…)`

- `BROKEN` → คำถามกลับเป็นค้างทันที ต้องตอบใหม่
- `HELD` ครบทุกข้อ → ชัดเจน

## 5. สถานะและป้ายตัวเลข

| สถานะ | เงื่อนไข | ป้าย |
|---|---|---|
| OPEN | ยังไม่มีคำตอบที่รับรอง · คำตอบ agent รอผู้ใช้ · UNCLEAR · สมมติฐานพัง | ค้าง (แดง) |
| WATCH | INFERRED ที่ยังตรวจสมมติฐานไม่ครบ · UNANSWERABLE | เฝ้าดู (เหลือง) |
| CLEAR | CONFIRMED · INFERRED ที่สมมติฐานผ่านครบ | ไม่นับ |
| DROPPED | ผู้ใช้เลิกติดตาม | ไม่นับ |

สถานะคำนวณตอนอ่านจากแถวคำตอบ / การรับรอง / ผลตรวจ — ไม่ถูกเก็บและไม่ sync

## 6. เพิ่มคำถาม

- **เก็บก่อน จัดทีหลัง** — บังคับแค่ตัวคำถาม และที่อยู่ (thesis หรือคำถามแม่) ที่เหลือเติมภายหลังได้
- สิ่งที่ยังขาดจะขึ้นใน `gaps`: `parent` (ยังไม่ผูกสาย) · `effect` (ยังไม่บอกว่าแต่ละคำตอบทำให้แม่ขยับอย่างไร) · `thought` (ยังไม่บอกว่าเห็นอะไรจึงสงสัย) — เติมด้วย `question_add_parent` / `question_set_effect` / แก้ `thought`
- ข้อเดียวที่ยังปฏิเสธ: `if_a` เหมือน `if_b` — เท่ากับบอกว่าคำตอบไม่เปลี่ยนอะไร
- ความเข้มอยู่ที่ **คำตอบ** ไม่ใช่คำถาม: กติกาหลักฐานใน §3 ไม่เปลี่ยน
- คำถามที่สองสายต้องการคำตอบเดียวกัน → อย่าถามซ้ำ ใช้ `question_add_parent` ให้มาบรรจบ
- หนึ่ง thesis มีรากข้อเดียว = คำถามตัดสินใจของ thesis นั้น
- แตก thesis เป็นหลายคำถามพร้อมกัน → `question_import` ครั้งเดียว: แต่ละข้อมี `key`, แม่อ้าง `key` ของข้อก่อนหน้าได้, แนบ `answer` ได้เลย; ข้อใดผิดกติกา จะไม่ถูกเขียนสักข้อ
