# Anti-Thesis — ถอยหนึ่งก้าว หาเหตุผลมาหักล้างสิ่งที่เชื่อ

**อัปเดตล่าสุด:** 2026-10-08
**ใช้เมื่อ:** ผู้ใช้สั่ง "step back" / ทบทวน thesis ด้วยการโต้แย้ง, เปิด PORT → TOOLS → THESES → ANTI-THESIS, หรือ `anti_queue` มีงานค้าง
**ใช้กับ:** ทุก agent — MCP ส่งไฟล์นี้ผ่าน tool `get_antithesis_spec` · resource `spec://anti-thesis` · prompt `step_back` (แก้ไฟล์ ไม่ต้องแก้ MCP)
**โค้ด:** `backend/routers/antithesis.py` · ตาราง `anti_*` ใน `backend/db.py` · หน้าจอ `views/portfolio/tabs/theses/anti/`

---

## 0. หลักการ

1. **ข้อที่ไม่เคยถูกท้า ยังไม่ผ่าน** — ความเชื่อที่ไม่มีใครโต้แย้งมีสถานะ `UNTESTED` ไม่ใช่ "ปลอดภัย"
2. **ยกข้อโต้แย้งถูก ปัดตกแพง** — ยกข้อโต้แย้งใช้แค่ประโยคเดียว; จะปัดตก (`REBUTTED`) ต้องมี zettel ที่มี URL + ประโยคที่อ้าง และ zettel นั้นต้องไม่อยู่ใน conflict ที่ยังเปิด — server ปฏิเสธ (422) ถ้าไม่ครบ
3. **ข้อที่ถูกท้าแล้ว แก้ข้อความไม่ได้** — เปลี่ยนสิ่งที่เชื่อ = เขียนข้อใหม่มาแทน (thesis → antithesis → synthesis) ข้อเดิมกับสิ่งที่เถียงกันไว้ถูกเก็บ ข้อใหม่เริ่มจาก `UNTESTED` แล้วถูกท้าอีกรอบ
4. **ผู้ใช้เป็นคนปิด** — คำตัดสินของ agent เป็น "ข้อเสนอ" จนกว่าผู้ใช้กดรับ; ถอนข้อโต้แย้ง / เขียนใหม่ตรง ๆ / เลิกใช้ / ลบ / เปลี่ยนน้ำหนักของข้อ เป็นสิทธิ์ผู้ใช้ (agent ได้ 403)
5. **ข้อหลักล้ม ไม่เปลี่ยน thesis เอง** — แสดง + ลง timeline (`ANTI_FALLEN`) ให้ผู้ใช้ตัดสิน เนื้อหา สถานะ และ conviction ของ thesis ไม่ถูกแตะ
6. **หน้าที่ของ agent ในงานนี้คือฝ่ายค้าน** — หาเหตุผลที่ thesis ผิด ไม่ใช่หาเหตุผลมาปกป้อง การยอมรับว่าข้อโต้แย้งชนะ (`CONCEDED`) เป็นผลลัพธ์ที่ดีเท่ากับการหักล้างได้

## 2. ข้อที่เชื่อ และด้านกลับ

| ช่อง | ใส่อะไร | ดี | ไม่ดี |
|---|---|---|---|
| `statement` | สิ่งที่ thesis ต้องการให้จริง หนึ่งประโยค ที่ผิดได้ | "อุปสงค์ HBM โตเร็วกว่าอุปทานไปจนถึงปี 2027" | "HBM น่าสนใจ" (หัวข้อ) · "หวังว่าราคาจะขึ้น" (ความหวัง) |
| `negation` | **สภาพของโลก** ถ้าข้อนั้นไม่จริง — ชัดพอจะไปหาได้ | "อุปทาน HBM ตามทันก่อนปี 2027" | "อุปสงค์ HBM ไม่โตเร็วกว่าอุปทาน" (แค่เติม "ไม่") |
| `stake` | `KEY` = ข้อนี้ล้ม thesis ล้ม · `SUPPORT` = ข้อเสริม | | ทุกข้อเป็น KEY |
| `basis` | ทำไมจึงเชื่อ (อ้าง Z-ref ในข้อความได้) | | |

- หนึ่งข้อ = หนึ่งความเชื่อ — "อุปสงค์โต **และ** อุปทานตึง" คือสองข้อ
- ข้อที่มีอยู่แล้วบนกระดานถูกปฏิเสธ (409) — ท้าข้อนั้นแทนการเขียนซ้ำ
- `negation` ว่างได้ตอนเก็บ แต่จะขึ้นใน `gaps` จนกว่าจะเติม (`anti_claim_update`)

## 3. มุมที่ท้า — ความเชื่อผิดได้ห้าแบบ

| `angle` | ข้อโต้แย้งมุมนี้บอกว่า | ตัวอย่าง |
|---|---|---|
| `FACT` | ข้อมูลที่ใช้ผิด เก่า หรือวัดคนละอย่างกับที่อ้าง | ตัวเลขอุปทานเป็นของปีก่อน ก่อนโรงงานใหม่เดินเครื่อง |
| `CAUSE` | สิ่งที่เห็นเกิดจากเหตุอื่น และเหตุนั้นไม่พา thesis ไปด้วย | ราคาขึ้นเพราะลูกค้าตุนของก่อนภาษี ไม่ใช่เพราะอุปสงค์จริง |
| `LOGIC` | ข้อมูลถูก แต่ข้อสรุปข้ามขั้นหรือเกินกว่าที่ข้อมูลรองรับ | อุปสงค์โตจริง แต่ไม่ได้แปลว่ากำไรต่อหน่วยโต |
| `TIME` | จริงวันนี้ แต่ไม่นานพอ ไม่กว้างพอ หรือมาช้ากว่ากรอบเวลาของ thesis | ตึงถึงกลางปี 2026 ไม่ถึง 2027 |
| `PRICE` | จริง แต่ตลาดรู้และจ่ายไปแล้ว หรือฝั่งตรงข้ามรู้มากกว่าเรา | consensus คาดไว้เท่านี้อยู่แล้ว ราคาสะท้อนครบ |
| `OTHER` | อื่น ๆ — ไม่นับเป็นมุมที่ต้องท้า | |

แต่ละข้อโต้แย้ง (`anti_object`):

| ช่อง | ความหมาย | บังคับ |
|---|---|---|
| `argument` | เหตุผลที่ข้อที่เชื่ออาจผิด หนึ่งประโยค | เสมอ |
| `angle` | มุมจากตารางบน | — (ไม่ใส่ = `OTHER`) |
| `would_see` | **ถ้าข้อโต้แย้งนี้จริง เราจะเห็นอะไร** — สิ่งที่ต้องไปหา | ไม่บังคับ แต่ขึ้น `gaps` จนกว่าจะมี |
| `look_where` | เอกสาร ตาราง หรือ tool ที่ใช้ดู | — |
| `parent` | A-ref ของข้อโต้แย้งที่ท้าต่อ (เช่น หลักฐานที่ใช้หักล้างมีปัญหา) | — |

กติกา:
- **ยกข้อที่แรงที่สุดของแต่ละมุม** — ไม่ใช่ข้อที่ตอบง่าย
- **อย่าเก็บข้อโต้แย้งไว้เพราะคิดว่าตอบได้** — ยกก่อน แล้วค่อยตอบด้วย `anti_verdict`
- **ข้อโต้แย้งไม่ถูกแก้** — ผิดข้อ / ซ้ำ → ผู้ใช้ถอน แล้วยกข้อที่ถูก
- ท้าข้อที่ถูกแทนที่หรือเลิกใช้ไม่ได้ (409) — ท้าข้อที่มาแทน

## 4. คำตัดสิน — `anti_verdict`

| `result` | ใช้เมื่อ | server ต้องการ |
|---|---|---|
| `REBUTTED` | ค้นแล้วพบว่าข้อโต้แย้งไม่จริง | `reasoning` · `evidence` ≥ 1 Z-ref ที่มี url + quote · ไม่มี evidence อยู่ใน conflict ที่เปิด |
| `CONCEDED` + `consequence=REVISE` | ข้อโต้แย้งจริง ข้อที่เชื่อต้องแคบลง | `reasoning` · `revised_statement` (ต่างจากเดิม) · ควรมี `revised_negation` |
| `CONCEDED` + `consequence=FALLS` | ข้อโต้แย้งจริง ข้อที่เชื่ออยู่ไม่ได้ | `reasoning` |
| `UNDECIDED` | ค้นแล้วยังบอกไม่ได้ | `reasoning` · `searched` · `next_check` (YYYY-MM-DD) |

- ถูกปฏิเสธ → อ่าน `missing` แล้วแก้ทุกข้อ หรือลดเป็น `UNDECIDED` **อย่าหักล้างด้วย zettel ที่ไม่ได้อ่าน**
- คำตัดสินของ agent = ข้อเสนอ (`PENDING`) ผู้ใช้กดรับหรือไม่รับ (ไม่รับต้องมีเหตุผล)
- `REVISE` ที่ผู้ใช้รับ → server เขียนข้อใหม่แทนข้อเดิมในธุรกรรมเดียวกัน: น้ำหนักเท่าเดิม, `round` +1, เริ่ม `UNTESTED`, ข้อโต้แย้งเดิมไม่ตามมา (ไม่ได้ถูกยกต่อข้อความใหม่)
- ตัดสินซ้ำได้ — แถวใหม่แทนแถวเดิม แถวเดิมอยู่ใน `history`
- `anti_none_found(claim, angle, searched)` — ค้นมุมนั้นจริงแล้วไม่พบข้อโต้แย้ง ต้องบอกว่าค้นที่ไหน; ถูกปฏิเสธ (409) ถ้ามุมนั้นมีข้อโต้แย้งอยู่แล้ว

## 5. สถานะ — คำนวณตอนอ่าน ไม่ถูกเก็บ

ข้อโต้แย้ง:

| สถานะ | เงื่อนไข |
|---|---|
| `OPEN` | ยังไม่มีคำตัดสินที่ผู้ใช้รับ |
| `PENDING` | agent ตัดสินแล้ว รอผู้ใช้ |
| `UNDECIDED` | ค้นแล้วยังบอกไม่ได้ (`due` = ถึง `next_check`) |
| `REBUTTED` | หักล้างแล้วด้วยหลักฐาน |
| `CONCEDED` | ข้อโต้แย้งชนะ |
| `WITHDRAWN` | ผู้ใช้ถอน — ไม่นับ |

ข้อที่เชื่อ:

| สถานะ | เงื่อนไข | นับเป็นงานค้าง |
|---|---|---|
| `UNTESTED` | ยังไม่มีข้อโต้แย้ง | ใช่ |
| `CONTESTED` | มีข้อโต้แย้งที่ `OPEN` / `PENDING` / `UNDECIDED` | ใช่ |
| `BROKEN` | ยอมรับข้อโต้แย้งแบบ REVISE แล้ว แต่ยังไม่มีข้อใหม่มาแทน | ใช่ |
| `STANDS` | มีข้อโต้แย้ง และทุกข้อถูกหักล้าง | — |
| `FALLEN` | ยอมรับข้อโต้แย้งแบบ FALLS | — (ข้อหลัก = แจ้งเตือน) |
| `REVISED` | มีข้อใหม่มาแทน | — |
| `RETIRED` | ผู้ใช้เลิกใช้ | — |

`state.angles` ต่อมุม: `untried` · `open` · `rebutted` · `conceded` · `none_found` · `state.settled` = `STANDS` และไม่มีมุม `untried`

ทั้ง thesis (`summary.verdict`):

| ค่า | ความหมาย |
|---|---|
| `KEY_FALLEN` | ข้อหลักล้ม — thesis ต้องทบทวน |
| `OPEN` | ยังมีข้อที่ไม่เคยถูกท้า หรือข้อโต้แย้งค้าง |
| `STANDING` | ทุกข้อยืน แต่ยังท้าไม่ครบทุกมุม |
| `SETTLED` | ทุกข้อยืน และถูกท้าครบทุกมุม — ไม่เหลือข้อโต้แย้ง |
| `EMPTY` | ไม่มีข้อที่ยืนอยู่บนกระดาน |

## 6. จบเมื่อไร

- **`SETTLED` คือจุดที่ step back รอบนี้จบ** — ทุกข้อที่เชื่อถูกท้าครบห้ามุม และทุกข้อโต้แย้งถูกหักล้างด้วยหลักฐานหรือค้นแล้วไม่พบ
- **ไม่ใช่ข้อพิสูจน์ว่า thesis ถูก** — แปลว่า "ยังหาเหตุผลมาหักล้างไม่ได้" ใครก็ยกข้อโต้แย้งใหม่ได้ทุกเมื่อ และข้อนั้นจะกลับเป็น `CONTESTED` ทันที
- ข้อที่ถูกเขียนใหม่เริ่มรอบใหม่จากศูนย์ — `round` บอกว่าข้อความนี้ผ่านการแก้มากี่ครั้ง
- ตัวเลขที่ข้อหนึ่งยืนหรือล้มตามมัน → ตั้งใน TRACK (`track_add`) · สิ่งที่ยังไม่รู้ → QUESTIONS — กระดานนี้เก็บ **การโต้แย้ง** ไม่เก็บตัวเลขและไม่เก็บคำถาม
