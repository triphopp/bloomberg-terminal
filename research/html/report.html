สรุปผู้บริหาร — Executive Summary

ขั้นที่ 2 — Z-Score Calculation (จุดวิกฤตอยู่ที่นี่)

ทุก layer ใช้สูตร Z-score เหมือนกัน:

$$ Z = \frac{X - \mu}{\sigma} $$

โดยที่:

$$ \mu = \frac{1}{N}\sum_{i=1}^{N} X_i \quad\quad \sigma = \sqrt{\frac{1}{N-1}\sum_{i=1}^{N}(X_i - \mu)^2} $$

สมมติฐานซ่อน: สูตรนี้ใช้งานได้ดีก็ต่อเมื่อ $X$ มาจาก distribution ที่มี finite variance และมี tails ที่ลดลงเร็วพอ (เช่น Gaussian) แต่ financial returns มี excess kurtosis สูง หมายความว่า events ที่ Z > 3 เกิดขึ้นบ่อยกว่าที่ Gaussian ทำนายไว้หลายเท่า

ขั้นที่ 3 — Threshold-based Scoring

แปลง Z-score ต่อเนื่องเป็น discrete score {−1, 0, +1}:

$$ \text{score} = \begin{cases} +1 & \text{if } Z > +\tau \\ -1 & \text{if } Z < -\tau \\ 0 & \text{otherwise} \end{cases} $$

Layer C ใช้ $\tau = 0.75$, Layer A และ B ใช้ $\tau = 0.50$

ขั้นที่ 4 — Weighted Confluence

$$ S_{\text{final}} = w_C \cdot s_C + w_B \cdot s_B + w_A \cdot s_A $$

น้ำหนักคงที่: $w_C = 0.40$, $w_B = 0.35$, $w_A = 0.25$

ขั้นที่ 5 — Probability Mapping (ปริยายจาก score)

ค่า $S_{\text{final}} \in [-1, +1]$ ถูกแปลงเป็น bullish/bearish probability โดยการ linear mapping หรือ logistic transformation ขึ้นอยู่กับ implementation แต่ปัญหาคือ ทั้ง pipeline ตั้งอยู่บน Z-score ที่ผิดหลักตั้งแต่ขั้นที่ 2

ส่วนที่ 03

จุดบกพร่อง #1 — Z-Score สมมติ Gaussian แต่ข้อมูลจริงเป็น Fat Tail

วิกฤต ปัญหาพื้นฐานที่สุด — Gaussian Assumption Violation

ปัญหาทางคณิตศาสตร์

Z-score แบบมาตรฐานสมมติว่าข้อมูลมาจาก distribution ที่มี kurtosis = 3 (mesokurtic) แต่ financial returns มี kurtosis ประมาณ 7–25 (leptokurtic) ผลที่ตามมาคือ:

เหตุการณ์ความถี่ตาม Gaussianความถี่จริง (empirical)ประเมินต่ำกว่าจริง
|Z| > 3σ0.27% (1 ใน 370 วัน)1–2% (1 ใน 50–100 วัน)4–7x
|Z| > 4σ0.006% (1 ใน 16,000 วัน)0.1–0.3% (1 ใน 300–1000 วัน)16–50x
|Z| > 5σ5.7 × 10⁻⁵%~0.01–0.05%175–875x

Welch (2024) ใน Financial Analysts Journal แสดงให้เห็นว่าเหตุการณ์ 19 ตุลาคม 1987 (Black Monday, return −17.1%) มี Z-score ประมาณ −17 ภายใต้ Gaussian assumption ซึ่งมีโอกาสเกิดขึ้น 1 ใน $10^{65}$ ครั้ง — ห่างไกลจากความเป็นจริงอย่างสิ้นเชิง

ผลกระทบต่อระบบ sector-tab.tsx

เมื่อตลาดเกิด extreme event (เช่น tariff shock เมษายน 2025):

1. Z-score ของ Layer A พุ่งไปที่ −4 หรือ −5 แต่ Gaussian ทำนายว่าเกิดได้ 1 ใน 16,000 วัน — ระบบจึง "ตกใจ" มากเกินไปกับสิ่งที่จริงๆ แล้วเกิดทุก 1–3 ปี

2. ในทางกลับกัน เมื่อ Z-score อยู่ที่ 2.5–3.0 ระบบอาจมองว่า "ยังปลอดภัย" แต่จริงๆ แล้วอยู่ใกล้ danger zone มากกว่าที่คิด

3. Probability output ทั้งหมดจึงเบี่ยงเบน เพราะ mapping จาก Z ไป probability ผิดตั้งแต่ต้น

แนวทางแก้ไข — Cornish-Fisher Adjusted Z-Score

ใช้ Cornish-Fisher expansion (Cornish & Fisher, 1937; ปรับปรุงโดย Maillard, 2012 และ Mark & Vaucher, 2023) เพื่อปรับ Z-score ให้คำนึงถึง skewness ($S$) และ excess kurtosis ($K$):

$$ Z_{CF} = Z + \frac{S}{6}(Z^2 - 1) + \frac{K}{24}(Z^3 - 3Z) - \frac{S^2}{36}(2Z^3 - 5Z) $$

โดยที่ $S$ = sample skewness, $K$ = sample excess kurtosis (kurtosis − 3) 

def cornish_fisher_z(z_raw, skew, excess_kurt):
    """
    ปรับ Z-score ด้วย Cornish-Fisher expansion
    Ref: Maillard (2012), Mark & Vaucher (2023)
    """
    z = z_raw
    s = skew
    k = excess_kurt
    
    z_cf = (z 
            + (s / 6) * (z**2 - 1)
            + (k / 24) * (z**3 - 3*z)
            - (s**2 / 36) * (2*z**3 - 5*z))
    return z_cf

แนวทางแก้ไขเสริม — Extreme Value Theory (EVT) สำหรับ Tail

สำหรับ events ที่เลย threshold $u$ (เช่น |Z| > 2) ใช้ Generalized Pareto Distribution (GPD) ตาม Peaks-Over-Threshold method แทนการใช้ Gaussian tail:

$$ P(X > x \mid X > u) = \left(1 + \xi \cdot \frac{x - u}{\beta}\right)^{-1/\xi} $$

โดยที่ $\xi$ คือ shape parameter (ค่าบวก = fat tail), $\beta$ คือ scale parameter วิธีนี้ได้รับการพิสูจน์ว่าให้ผลแม่นยำกว่า Gaussian อย่างมากจาก Arian et al. (2020) "Uncertain EVT" ที่ให้ threshold เป็น dynamic random variable

จุดบกพร่อง #2 — Sigma Floor ไม่สม่ำเสมอ ทำให้ Z-Score ระเบิด

วิกฤต Sigma Floor Inconsistency → Z-Score Explosion

ปัญหาทางคณิตศาสตร์

ในช่วง low-volatility ที่ยืดเยื้อ (เช่น 2017, 2019) ค่า $\sigma$ จาก rolling window จะลดต่ำลงมาก เมื่อเกิด small shock Z-score จะพุ่งสูงผิดปกติ:

$$ \text{ถ้า } \sigma \to 0^+ \text{ แล้ว } Z = \frac{X - \mu}{\sigma} \to \pm\infty $$

Document ระบุว่าใช้ σ = max(σ_realized, σ_long_run) ใน risk table แต่ไม่ได้ implement จริงใน pseudocode — แต่ละ layer จึงคำนวณ sigma ต่างกัน

ตัวอย่างเชิงตัวเลข

สถานการณ์σ (rolling 252d)ShockZ-scoreปัญหา
Post low-vol (2017)0.003−0.015−5.0เกินจริง — shock ปกติดูเหมือน crisis
Post high-vol (2020)0.025−0.015−0.6ปกติ — signal ถูกต้อง

แนวทางแก้ไข — Unified Sigma Floor Utility

def safe_zscore(series, rolling_window=252, sigma_floor_pct=0.30):
    """
    คำนวณ Z-score พร้อม sigma floor สม่ำเสมอทุก layer
    sigma ต้องไม่ต่ำกว่า 30% ของ long-run sigma
    Ref: Moreira & Muir (2017) — Volatility-Managed Portfolios
    """
    mu = series.rolling(rolling_window).mean()
    sigma = series.rolling(rolling_window).std()
    
    # Sigma floor: ป้องกัน Z-score explosion
    long_run_sigma = sigma.expanding().mean()
    sigma_floor = long_run_sigma * sigma_floor_pct
    sigma_safe = sigma.clip(lower=sigma_floor)
    
    z = (series - mu) / sigma_safe
    return z

จุดบกพร่อง #3 — Fixed Threshold ไม่มี Statistical Calibration

วิกฤต Threshold เลือกโดยไม่มี empirical justification

ปัญหาทางคณิตศาสตร์

Threshold ±0.75 สำหรับ Layer C และ ±0.50 สำหรับ Layer A, B ถูกเลือกแบบ ad hoc ไม่มี calibration กับข้อมูลจริงว่าให้ precision/recall ที่ดีเพียงใดสำหรับ regime detection ปัญหาที่ตามมาคือ:

1. ถ้า threshold ต่ำเกินไป → False positive สูง ระบบส่ง signal มากเกินไป signal ไม่มีคุณค่า
2. ถ้า threshold สูงเกินไป → False negative สูง ระบบพลาด regime change ที่สำคัญ
3. ไม่ได้ปรับตาม distribution จริง → Z = 0.5 ใน Gaussian ≠ Z = 0.5 ใน fat-tailed distribution

แนวทางแก้ไข — Information Coefficient Calibration

ใช้ Spearman IC (Information Coefficient) ระหว่าง score กับ future returns ใน out-of-sample period เพื่อหา threshold ที่ optimal:

$$ \tau^* = \arg\max_\tau \; \rho_S\bigl(\text{score}(Z, \tau),\; r_{t+h}\bigr) $$

โดย $\rho_S$ คือ Spearman rank correlation, $r_{t+h}$ คือ forward return ระยะ $h$ วัน ทดสอบ $\tau \in \{0.25, 0.50, 0.75, 1.00, 1.25\}$ แล้วเลือกค่าที่ให้ IC สูงสุดในข้อมูล out-of-sample

จุดบกพร่อง #4 — Fixed Weight ไม่ปรับตาม Regime

สูง Static Weights ไม่สะท้อน Data Quality หรือ Market Regime

ปัญหาทางคณิตศาสตร์

Weight $w_C=0.40, w_B=0.35, w_A=0.25$ คงที่ตลอดเวลา มี 2 ปัญหา:

ปัญหา A — Data Staleness: Layer C อัปเดตรายไตรมาส ถ้าเป็นเดือน 2 หลังจากข้อมูลล่าสุด Layer C จะ stale แต่ยังได้ weight 40% เท่าเดิม — ควรลด weight ลงเมื่อข้อมูลเก่า

ปัญหา B — Regime Blindness: ในช่วง crisis (VIX > 35) Layer B (fund flows) ถูก distort จาก mechanical rebalancing ของ model portfolios ไม่ใช่ sentiment จริง แต่ระบบยังให้ weight 35% เท่าเดิม

แนวทางแก้ไข — Dynamic Quality-Adjusted Weights

$$ w_k^{\text{eff}} = w_k^{\text{base}} \times \begin{cases} 1.0 & \text{if layer $k$ is fresh} \\ 0.3 & \text{if layer $k$ is stale} \end{cases} $$
$$ \hat{w}_k = \frac{w_k^{\text{eff}}}{\sum_{j} w_j^{\text{eff}}} \quad\quad S_{\text{final}} = \sum_k \hat{w}_k \cdot s_k $$

Layer ที่ stale ได้ weight ลดลง 70% แล้ว renormalize ให้ผลรวม = 1 อ้างอิง Ilmanen & Kizer (2012) และงานวิจัยรุ่นใหม่ที่แนะนำ regime-adaptive weights

ส่วนที่ 07

จุดบกพร่อง #5 — ไม่มี Macro Regime Filter (Tail Event Blind)

สูง ระบบไม่สามารถรับรู้ Macro Stress → Fat Tail Events ผ่านเข้ามาโดยไม่มีตัวกรอง

ปัญหาทางคณิตศาสตร์

ระบบปัจจุบันไม่มี mechanism สำหรับ downscale confidence เมื่อ macro environment อยู่ใน stress regime ในช่วง tariff shock เมษายน 2025 equity ETF flows ยังเป็นบวก (นักลงทุนซื้อ dip) แต่ fundamental outlook แย่ลงมาก → Layer B ให้ false positive

นี่คือจุดที่ fat tail เข้ามาเล่นงานโดยตรง: เมื่อ VIX > 35, credit spread > 500 bps, หรือ yield curve inverted ลึก (< −0.50%) — ข้อมูลที่ใช้คำนวณ Z-score ไม่ได้มาจาก "same distribution" อีกต่อไป เกิด regime switch ที่ทำให้ Z-score ที่คำนวณจาก historical window ไม่มีความหมาย

แนวทางแก้ไข — Macro Override Layer

$$ S_{\text{adjusted}} = S_{\text{final}} \times \lambda_{\text{macro}} $$

โดยที่ $\lambda_{\text{macro}} \in [0.2, 1.0]$ กำหนดจากจำนวน stress flags:

$$ \lambda_{\text{macro}} = \max\bigl(0.2,\; 1.0 - 0.3 \times n_{\text{flags}}\bigr) $$

ส่วนที่ 08

จุดบกพร่อง #6 — 20-Day Lookback เดียวไม่จับ Multi-Horizon Signal

ปานกลาง Single Lookback ไม่เสถียรเพียงพอสำหรับ allocation signal

ปัญหาทางคณิตศาสตร์

Layer A ใช้ lookback 20 วันเดียว (~1 เดือน) ซึ่ง Moskowitz et al. (2012) พิสูจน์ว่า time-series momentum มีพลังที่สุดที่ 12-month lookback ส่วน 20 วันอยู่ใน "no man's land" ระหว่าง short-term reversal (1–5 วัน) และ medium-term momentum (3–12 เดือน)

แนวทางแก้ไข — Blended Lookback

$$ Z_{\text{blended}} = \sum_{i=1}^{3} w_i \cdot Z_{\text{lb}_i} \quad\text{where } \text{lb} \in \{20, 60, 120\} \text{ days} $$

ใช้น้ำหนัก $w = [0.50, 0.30, 0.20]$ เพื่อให้ short-term ยังมี real-time sensitivity แต่ medium-term ช่วย smooth noise ออก ลด whipsaw signal อ้างอิง Moskowitz et al. (2012) และ AQR research (2024)

ส่วนที่ 09

จุดบกพร่อง #7 — ไม่มี Volatility Scaling เป็น Default

ปานกลาง Z-score ไม่ปรับตาม Realized Volatility

ปัญหาทางคณิตศาสตร์

ในช่วง high-volatility Z-score พุ่งสูงผิดปกติเพราะ denominator ($\sigma$) จาก rolling window ล่าช้ากว่า realized vol จริง (lagging indicator) ทำให้ signal เกินจริง

Moreira & Muir (2017) ใน Journal of Finance พิสูจน์ว่า volatility-managed portfolios ที่ scale exposure ตาม inverse ของ realized vol ให้ Sharpe ratio สูงกว่า unmanaged portfolios อย่างมีนัยสำคัญ

แนวทางแก้ไข — Volatility-Adjusted Z-Score

$$ Z_{\text{adj}} = Z_{\text{raw}} \times \frac{\sigma_{\text{target}}}{\sigma_{\text{realized}}} $$

โดย clip scaling factor ไว้ที่ $[0.25, 4.0]$ เพื่อป้องกัน extreme scaling:

$$ \text{scale} = \text{clip}\left(\frac{\sigma_{\text{target}}}{\sigma_{\text{realized}}},\; 0.25,\; 4.0\right) $$

Research Papers ที่แก้ปัญหา Fat Tail

รายการ papers หลักที่เกี่ยวข้องโดยตรงกับการแก้ไขจุดบกพร่องในระบบ เรียงตามลำดับความสำคัญต่อการ implement:

1
Statistical Consequences of Fat Tails: Real World Preasymptotics, Epistemology, and Applications
Nassim Nicholas Taleb (2020, 3rd ed.)
Technical Incerto, arXiv: 2001.10488
แก้จุดบกพร่อง #1 — ตำราหลักที่พิสูจน์ว่า sample mean, sample variance, และ Z-score ทั้งหมดไม่ converge ตามที่ classical statistics ทำนายเมื่อ distribution มี fat tail แนะนำการใช้ robust estimators แทน moment-based statistics
2
A Heuristic for Fat-Tailed Stock Market Returns
Ivo Welch (2024)
Financial Analysts Journal, pp.18–26
แก้จุดบกพร่อง #1, #2 — เสนอ adjusted Z-score ($Z'$) สำหรับ fat-tailed returns โดยแสดงว่า unadjusted Z-score ประเมินโอกาส extreme events ผิดไปหลายระดับ (Black Monday: Z = −17 ภายใต้ Gaussian ซึ่งเป็นไปไม่ได้)
3
Risk Parity Portfolio Optimization under Heavy-Tailed Returns and Time-Varying Volatility
Marc S. Paolella et al. (2023)
University of Zurich Working Paper
แก้จุดบกพร่อง #4, #7 — ใช้ elliptical multivariate generalized hyperbolic distribution (ไม่สมมติ Gaussian) ร่วมกับ Expected Shortfall แทน VaR เป็น risk measure พิสูจน์ว่า allocation ที่คำนึงถึง fat tails มี sensitivity ต่อ volatility shocks น้อยกว่า และให้ portfolio turnover ต่ำกว่า

⚠ Fat Tail ไม่สามารถ "แก้" ได้ 100% — ทำได้แค่ลดผลกระทบ

ตามที่ Taleb (2020) เน้นย้ำ: fat tail distributions มีคุณสมบัติที่ sample statistics (mean, variance, Z-score) ไม่ converge ตาม classical asymptotics ไม่มี model ใดจะจับ tail events ได้ 100% สิ่งที่ทำได้คือ:

1. รู้ตัวว่า model ผิด → ไม่ overconfident ใน probability output
2. ใช้ robust estimators → Cornish-Fisher, EVT แทน Gaussian Z-score
3. มี circuit breaker → Macro Override ที่ลด confidence ในช่วง stress
4. Backtest สม่ำเสมอ → ตรวจสอบว่า out-of-sample performance ยังสอดคล้อง
